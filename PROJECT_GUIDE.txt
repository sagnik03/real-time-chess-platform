CHESS GAME PROJECT GUIDE
========================

Last updated: 2026-06-18

1) PROJECT OVERVIEW
-------------------
This project is a browser-based chess board implementation using plain JavaScript modules.
It renders an 8x8 board, places all pieces in standard starting positions, and currently
implements click-based movement flow for pawns (with square highlighting).

2) TECH STACK
-------------
- HTML5
- CSS3
- Vanilla JavaScript (ES Modules)
- Static asset loading (SVG images for pieces)
- No frontend framework
- No backend
- No package manager dependency (runs directly in browser)

3) FOLDER AND MODULE GUIDE
--------------------------
Root files:
- index.html: Base page shell and root mount node.
- index.js: App entry point. Initializes rendering and global click events.

Data layer:
- Data/data.js: Creates board state objects (8 rows x 8 columns).
- Data/state.js: Holds and exports global state generated by initGame().
- Data/pieces.js: Piece factories for black/white pieces with image path + piece_name.
- Data/data.json: Small metadata placeholder file.

Render layer:
- Render/main.js:
  - Initializes board DOM.
  - Assigns initial pieces to squares.
  - Renders piece images.
  - Handles square highlight visuals.
  - Moves piece DOM node and syncs data state via moveElement().

Events layer:
- Events/global.js:
  - Global click delegation on root board container.
  - Selects pawn logic by piece type.
  - Computes and renders candidate move highlights.
  - Executes movement to clicked highlight target.

Helpers:
- Helper/constants.js: Shared DOM constants (ROOT_DIV).

Styling:
- style/index.css: Board layout, square colors, highlight styles, and piece image sizing.

Assets:
- Assets/images/pieces/black: Black piece SVGs.
- Assets/images/pieces/white: White piece SVGs.

4) CURRENT IMPLEMENTATION STATUS
--------------------------------
Implemented:
- Dynamic generation of board squares with IDs a1-h8.
- Alternating square colors.
- Initial placement of all chess pieces.
- Click-based interaction for white pawns and black pawns.
- Pawn forward move highlighting:
  - White pawn from rank 2 can move 1 or 2 squares forward.
  - Black pawn from rank 7 can move 1 or 2 squares forward.
  - Otherwise single-square forward highlight.
- Selected piece square self-highlight.
- Move execution updates:
  - Data state (piece reassignment between source/target squares).
  - DOM movement for piece image.
  - Cleanup of prior highlights/selections.

Partially implemented / prepared:
- Pawn diagonal capture variables are declared in white pawn logic but not completed.

Not implemented yet:
- Move legality checks for blocked paths.
- Pawn capture rules (full behavior).
- En passant.
- Promotion.
- Castling.
- Check/checkmate/stalemate logic.
- Turn management (white/black turn order enforcement).
- Move history and undo.
- Rules for non-pawn pieces during gameplay events.

5) HOW THE APP BOOTS
--------------------
1. index.html loads style/index.css and index.js.
2. index.js calls:
   - initGameRender(globalState)
   - GlobalEvent()
3. Render/main.js builds board and places pieces.
4. Events/global.js listens for user clicks and applies movement behavior.

6) KNOWN CODE NOTES
-------------------
- Data/data.js has a Greet() helper that is currently unused.
- In Events/global.js, some temporary variables (for example flatArray or captureIds)
  are declared but not used in all branches.
- Rendering and state are synchronized manually, so future rule additions should keep
  both in sync to avoid visual/state mismatches.

7) RUN INSTRUCTIONS
-------------------
Because this is a static web app, you can run it with any static server or directly open
index.html in a browser. For module loading reliability, serving with a local static server
is recommended.
